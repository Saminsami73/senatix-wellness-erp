1. STRICT 60 FPS PERFORMANCE, LIGHT UI & RESPONSIVE ENGINEERING RULES
--------------------------------------------------------------------------------
A. STRICT 60 FPS RENDERING RULES (MANDATORY FOR ALL COMPONENTS):
   1. NO Heavy CSS Blurs on Scrolling Lists:
      - Do NOT use `backdrop-blur-md` or `backdrop-filter` on repeating cards, table rows, or mobile drawers (causes severe GPU lag on budget smartphones).
      - Use clean, solid Light Mode surfaces: Page Background `bg-slate-50` (#F8FAFC), Card Surface `bg-white` (#FFFFFF), Crisp Border `border border-slate-200` (#E2E8F0), Subtle Elevation `shadow-sm`.
   2. GPU-Accelerated Micro-Interactions Only:
      - Only animate `transform` (`translate3d`, `scale`) and `opacity`.
      - Transition duration must be fast and snappy: `transition-all duration-150 ease-out` (`150ms`).
      - Active tap feedback on all buttons: `active:scale-[0.98]` so users feel an instant physical response on touchscreens.
      - Remove continuous infinite animations (`animate-pulse`) except on skeleton loading placeholders.
   3. Zero Layout Shift (CLS = 0) for Optional Images:
      - Every product photo and user avatar MUST sit inside a fixed-dimension square or circle container (`w-11 h-11` or `w-14 h-14 aspect-square shrink-0 overflow-hidden`) so the screen never jumps while images load.
      - Always use `loading="lazy"` and `decoding="async"` on `<img>` tags.
   4. Instant List Filtering & Pagination (No DOM Bloat):
      - Never render more than 30 rows/cards on the screen at once. Use client-side pagination (`25 items per page`) or virtualized lists (`useMemo` + debounced search input at `120ms`).
      - Switching tabs or typing in search boxes must respond in `<16ms` (60 FPS).

B. UNIVERSAL RESPONSIVE LAYOUT ARCHITECTURE (ALL SCREEN SIZES):
   1. Small & Standard Mobile Phones (`320px` to `767px` - `< md`):
      - Navigation: Fixed Top Header (`h-14`) showing Senatix Logo, Current Page Title, and Logged-in User's Circular Photo/Avatar + Fixed Bottom Navigation Bar (`h-16`) with 5 large tap targets (`Home`, `Make Bill`, `Stock`, `Money Book`, `More Menu`).
      - Data Display: Tables automatically transform into clean **Mobile Info Cards** (`md:hidden`) with big readable text, photo thumbnail on the left, price/stock badge on the right, and full-width action buttons at the bottom. Zero horizontal scrolling required.
      - Billing Screen on Mobile: Medicine list fills the screen; a **Sticky Bottom Cart Bar** shows `"Items in Bill: X | Total: ৳ Y,YYY [Review & Confirm ->]"` which opens a smooth slide-up drawer.
      - Input Font Size Rule: All `<input>`, `<select>`, and `<textarea>` elements MUST have `text-base` (`16px` minimum) so iOS/Android browsers never auto-zoom the screen when a worker taps an input box.
   2. Tablets (`768px` to `1023px` - `md` to `lg`):
      - Navigation: Left Collapsible Icon+Label Sidebar (`w-20` collapsed, `w-60` expanded).
      - Layouts: 2-column summary grids (`grid-cols-2`), compact tables with touch-friendly `h-11` buttons.
   3. Office Laptops & Desktops (`1024px` to `1920px+` - `lg` & `xl`):
      - Navigation: Permanent Left Sidebar (`w-64`) with Senatix Branding, User Profile Card (Photo + Name + Role Badge), and instant route links.
      - Layouts: 4-column KPI cards (`grid-cols-4`), full multi-column data tables (`hidden md:table`) with sticky table headers, and **Split-Screen POS Billing** (60% Left: Searchable Medicine Grid with Photos; 40% Right: Sticky Live Invoice Cart & Payment Calculator).

2. OPTIONAL IMAGE SYSTEM & FREE-TIER STORAGE ARCHITECTURE
================================================================================
Every entity in the software supports an **OPTIONAL** photo (`image_url TEXT NULLABLE`).

A. WHO & WHAT CAN HAVE AN IMAGE (ALL OPTIONAL):
   1. Products / Medicines (`products.image_url`): Photo of the medicine box, strip, or bottle so staff and delivery men can visually recognize the product immediately.
   2. Executors / Super Admins / Managers / Accountants / Store Keepers / Field Staff (`employees.image_url` & `profiles.avatar_url`): Profile photo of every person in the company (50+ staff + owners/executors).
   3. Pharmacies / Customers (`customers.image_url`): Optional photo of the pharmacy signboard or shop owner.
   4. Suppliers / Factories (`suppliers.image_url`): Optional factory/brand logo.
   5. Company Branding (`company_settings.logo_url`): Senatix Wellness logo for the top header and printed PDF invoices.

B. CLIENT-SIDE AUTO-COMPRESSION ENGINE (`lib/imageUpload.ts`):
   To keep the Supabase Free Tier (1 GB limit) running forever at 60 FPS:
   - Before uploading any selected photo (`JPG`, `PNG`, `HEIC`, `WebP`), a browser-side `<canvas>` helper function automatically:
     1. Crops/resizes the image to max `400x400px` (maintaining aspect ratio).
     2. Converts and compresses the image to `image/webp` at `0.75` quality (resulting file size: **15 KB to 35 KB**).
     3. Uploads the tiny `.webp` file to the public Supabase Storage bucket `senatix-media` under folder paths:
        - `products/{product_id}.webp`
        - `staff/{emp_id}.webp`
        - `customers/{customer_id}.webp`
        - `suppliers/{supplier_id}.webp`
     4. Saves the public URL in the table's `image_url` column with `cacheControl: '31536000'` (1-year browser cache).
   - Includes a `"Remove Photo"` button if the user wants to clear the photo back to `NULL`.

C. SMART VISUAL FALLBACK COMPONENT (`components/ui/SmartAvatar.tsx`):
   - If `image_url` is present: Renders the compressed WebP image inside a rounded container (`rounded-xl` for products, `rounded-full` for people).
   - If `image_url` is `NULL` (not uploaded):
     * For People (Admin, Executor, Staff, Customer Owner): Renders a crisp pastel circle with their 2-letter Initials (e.g., `SA` for Samin, `AR` for Executor/Director).
     * For Products: Renders a color-coded category icon (`Pill` for Tablet/Capsule, `FlaskConical` for Syrup, `Syringe` for Injection, `Package` for Supplement/Box).
